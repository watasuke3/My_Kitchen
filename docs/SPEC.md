# 機能要件（SPEC.md）

献立アプリ **My_Kitchen** の機能要件を定義する。
プロジェクト概要・技術構成は [README.md](../README.md) を、技術判断や設計の経緯は [DESIGN.md](../DESIGN.md) を参照。

---

## 1. ユーザー属性とログイン
- **認証**: ID（メールアドレス）とパスワードによるログイン。
- **身体プロファイル**:
    - 性別 / 身長 / 体重 / 年齢 / 活動レベル（低い・ふつう・高い）
- **目標設定**: ダイエット / 維持 / 筋力アップ など、初期登録時に選択（後から変更可）。
- **アレルギー・嫌いな食材**: 登録した食材は献立提案・自動生成から除外。
- **自動計算**:
    - 基礎代謝量は **国立健康・栄養研究所の式（Ganpule の式）** で算出。
    - 1日あたりの必要カロリー = 基礎代謝 × 活動レベル係数。
    - 目標栄養素量（PFC）を目標設定に応じて算出。

## 2. セキュリティ要件
- **パスワード保存**: bcrypt（または argon2）でハッシュ化。平文保存禁止。
- **通信**: 全通信を HTTPS で暗号化。
- **セッション管理**: HttpOnly + Secure Cookie、または JWT（短命のアクセストークン＋リフレッシュトークン）。
- **XSS/CSRF 対策**: フレームワークの標準機構を有効化。ユーザー入力はエスケープ／サニタイズ。
- **レート制限**: ログインAPIに試行回数制限（ブルートフォース対策）。
- **パスワードポリシー**: 最低8文字、英数字を含む。

## 3. レシピ管理機能
- **レシピの種類**:
    - アプリ提供（Preset）
    - ユーザー自作（User-Original）：ゼロからの追加が可能。
    - 調整済み（Derived）：既存レシピのコピー＆カスタマイズ。**作成したユーザー本人のみ閲覧・編集可能。**
- **分類**: 登録時に「主食」「主菜」「副菜」「汁物」「その他」から選択。
- **人数（分量）スケーリング**: レシピは基準人数（例：2人前）を持ち、献立に組み込む際に **任意の人数に拡縮**できる。具材の数値も連動して再計算される。
- **具材管理**:
    - **メイン食材**: 数値（g／個など）で管理し、栄養計算に反映。
    - **調味料**: 原則として数値で管理し、栄養計算に反映。栄養への影響が極小なもの（「少々」「適量」など）はテキストメモでも可。
- **調理手順**: 各レシピに作り方（順序付きステップ）を登録できる。

## 4. カレンダー・献立管理機能
- **ウィークリープラン**: 1週間分（朝・昼・晩）の献立を決定。
- **重複回避**: 自動提案時、**直近1週間（設定で最大2週間まで延長可）に登場した献立は候補から除外**。
- **食事実績の記録**: ユーザーが手動で「食べた」ボタンを押した時点で実績として記録。
- **スキップ管理**: 食べなかった献立には「食べなかった」フラグを付与し、栄養集計から除外。
- **履歴参照**: 過去の食事実績をカレンダー画面から閲覧可能。
- **買い物リスト**: 献立確定後、必要な材料のチェックボックス付きリストを自動生成。
    - **既存在庫の除外**: ユーザー自身でチェックを入れて除外する運用。
    - **食材の合算**: 複数献立で同じ食材が登場する場合は **合計値で表記**。
    - **同期**: チェック状態はサーバーに保存し、別端末でも反映される。

## 5. 栄養分析・フィードバック
- **栄養計算**: レシピ内の数値化された具材・調味料を基に、リアルタイムで栄養価を算出。
- **フィードバック**:
    - 必須栄養素に対する充足率の提示。
    - ユーザーが指定したタイミング（食後、1日の終わり、週末など）でアドバイスを表示。
    - 「食後」フィードバックは **ユーザーが「食べた」ボタンを押した時点** をトリガーとする。

## 6. 今後の拡張機能（ロードマップ）
- **マルチデバイス強化**: リアルタイム同期、プッシュ通知、競合解決などの本格対応。
- **パーソナライズ提案**: 目標（ダイエット／筋力アップ等）に合わせた献立の自動提案の高度化。
- **画像認識**: 写真アップロードによる食材の自動判別・記録。
- **栄養オーダー**: 「低糖質」「高タンパク」など、週単位での栄養バランス指定。
