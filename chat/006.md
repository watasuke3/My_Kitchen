# suke
カレントディレクトリにchatディレクトリがあれば必ずそこにmdファイルを作成しそこに追記してください。/clearで履歴を削除したり、セクションが変われば次のmdファイルを作成してください。ファイルネームは001.mdのような番号順にしてください。(今はもう005.mdまで存在しています)

# assistant
この仕様は前回実装した`SESSIONS_LOG.md`用フックと設計がかなり異なるため(保存先ディレクトリ、ファイル分割単位、フォーマットが違う)、実装前に3点確認させてください。

実装します。まず SessionStart 用フックを新規作成します。

次にStopフック側を`chat/`ディレクトリ書き込み用に全面改修します(Fable5指摘のバグ修正も併せて反映)。

次に`settings.json`にSessionStartフックを追加します。

パイプテストを行います。まずSessionStartのシミュレーションから。

SessionStartフックで006.mdが正しく作成されました。次にStopフックの動作確認をします。

想定通り`006.md`に既存フォーマットで正しく追記されました。次に、新しい`.active_chat_file`ステートファイルなしでStopが呼ばれた場合の自己修復ロジックも確認します。

自己修復(既存の最大番号ファイルに復帰)と、chatディレクトリが無い場合の無害な終了、両方確認できました。JSON構文とフック登録を最終検証します。

実際のプロジェクトディレクトリに対して1回だけ`chat-log-start.sh`を手動実行し、`006.md`を用意します(このセッションは新フック登録前に開始しているため、自動発火の機会がまだ無かったためです)。

`006.md`と状態ファイルの準備ができました。不要になった`SESSIONS_LOG.md`とテスト用ディレクトリを削除します。
